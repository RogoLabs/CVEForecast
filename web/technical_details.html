Project Overview

CVE Forecast predicts how many Common Vulnerabilities and Exposures will be published, using an ensemble of time series models whose hyperparameters are retuned monthly. Every forecast is scored against what was actually published, and those results are shown next to it.

Real-World Validation

Historical backtest on 2025 data (Jan-Sep) with actual vs. predicted comparisons. ranked by MASE over rolling forecast origins — see the dashboard for current figures.

Unified Pipeline

Single command execution for CVE + CNA forecasting. Automated daily updates and monthly hyperparameter tuning via GitHub Actions.

Accuracy Tracking

ForecastTracker accumulates prediction snapshots over time, enabling long-term accuracy analysis and model stability assessment.

Modular Architecture

Clean separation between data loading, training, forecasting, and validation. BaseForecaster and ValidationMixin provide extensible framework.

CVE Forecasting Pipeline

The CVE forecasting pipeline uses 13 production-ready models with optimized hyperparameters, historical backtest validation, and transparent performance metrics.

Core Components

  • run_production_forecast.py: Unified pipeline entry point
  • cve_adapter.py: CVE forecasting implementation
  • base_forecaster.py: Abstract base class
  • validation_mixin.py: Backtest validation
  • forecast_tracker.py: Accuracy tracking over time
  • data_loader.py: Processes 297K+ CVE JSON files

Production Models (16, incl. naive baselines)

Statistical (8): Prophet, AutoARIMA, TBATS, Theta, FourTheta, ExponentialSmoothing, KalmanFilter, Croston
ML/Tree (5): XGBoost, LightGBM, CatBoost, RandomForest, LinearRegression

Ranking: by MASE over rolling forecast origins, with naive baselines scored alongside. Current figures are on the dashboard — they are not duplicated here because they move as data arrives.

Rolling-Origin Validation

Real-World Accuracy Testing: Each model is backtested by training on data through 2024 and forecasting Jan-Sep 2025, then comparing predictions against actual published CVE counts.

  • Forecast vs Published Table: Month-by-month comparison with error percentages and performance ratings
  • Model Rankings: Real-time leaderboard sorted by backtest MAPE
  • Transparent Metrics: MAE, MAPE, and performance badges (Excellent < 5%, Good < 10%, Fair < 20%)
  • Historical Tracking: ForecastTracker accumulates snapshots for long-term accuracy analysis

Automated Workflows

GitHub Actions Integration:

  • Daily Forecast: Runs at midnight UTC, generates fresh forecasts, deploys to GitHub Pages
  • Monthly Tuning: Runs 1st of each month, optimizes hyperparameters, updates config.json
  • Zero Downtime: Continuous deployment with automatic rollback on failure
  • Artifact Storage: 90-day retention of tuning results and execution logs

CNA Forecast

CNA Forecast provides organization-specific vulnerability disclosure predictions through a dedicated pipeline optimized for individual CVE Numbering Authorities.

Core Components

  • cna_main.py: Orchestrates CNA-specific forecasting workflow
  • cna_config.json: CNA-optimized model configurations
  • cna.js: Interactive visualization and table management
  • cna_forecast.html: Dedicated CNA dashboard interface
  • cna-*.js: Specialized chart and utility modules

Model Selection (CPU-Optimized)

Primary: ExponentialSmoothing - Robust statistical forecasting
ML Ensemble: LightGBM, XGBoost - High-performance gradient boosting
Statistical: Prophet - Time series with seasonality
Baseline: LinearRegression - Simple trend modeling

Intelligent Model Selection

Organization-Specific Optimization: Each CNA's unique vulnerability disclosure patterns are analyzed to select the best-performing model based on validation MAPE scores.

  • Validation-Based Selection: Models tested on historical data with automatic fallback mechanisms
  • Performance Tracking: MAPE scores recorded for transparency and model comparison
  • Adaptive Configuration: Hyperparameters optimized per organization's data characteristics
  • Robust Error Handling: Graceful degradation when models fail on insufficient data

CNA-Specific Features

  • Model Transparency: Clear indication of which model was selected for each organization

Release History

v0.13 - Ockham (September 2026)

The front end, rebuilt — the dashboard says what it can defend and drops what it could not.

Forecasts

  • The interval leads. The headline is the 80% range, not a point estimate. A single figure twelve to sixteen months out claims a precision the models do not have, and the interval is the output whose coverage is actually measured — 80.7% empirical against a nominal 80%.
  • The comparison with last year is a range too, quoted as a multiple, because a single growth figure against a range forecast puts the false precision straight back.
  • Modelled figures round to the nearest thousand; counts do not. Published totals are observed, so they stay exact, and the rounding becomes the signal for which numbers are estimated.
  • The chart leads with the ensemble — the line, the band and the headline now all describe the same thing — and closes on a labelled interval bracket rather than a single value.

Rebuilt

  • Tailwind's play CDN is gone. It warns in the console that it is not for production, and because its dark: variant is unusable from the CDN, dark mode had been hand-patched with roughly 470 lines of !important overrides — 41% of the old stylesheet, written twice. app.css replaces it with tokens, and contains no !important at all.
  • All four pages share one design system and one page shell, instead of duplicating the header, footer, analytics snippet and theme script in each file.
  • Numeric columns are right-aligned with tabular figures, and colour is reserved for judgements rather than spent on the direction of an error.

Corrected

  • Forecast history table alignment. Five column headers, six cells — every value after the forecast column rendered one column left of its heading, the same defect the rankings table carried before v0.12.
  • CNA sort indicators. Arrows were written into a span while aria-sort was never set, so the visible state and the accessible one were separate facts and only one existed.
  • Charts follow the theme. Colours were read once when a chart was built, so switching theme by any route other than the toggle left one theme's gridlines on the other's background.
  • Mobile navigation. The old nav overflowed its own header band and pushed the document to 510px at a 375px viewport; no page scrolls sideways now.
  • The evolution chart no longer dramatises small revisions. Its y-axis was fitted to the data, so a change of a few tenths of a percent filled the panel and read as a collapse.

Known gap

  • CNA forecasts have no interval. The per-CNA pipeline emits a point forecast and a validation MASE; the residuals that would build a band are computed on every run and discarded, and the backtest is configured with just enough origins to sit on the minimum the interval code requires. Those pages name the model and its MASE instead of implying a precision that has not been measured.

v0.12 - Delphi (September 2026)

Calibration & Correction — the forecast now reflects the data, the accuracy figures describe the published forecast, and the uncertainty is visible.

Corrected

  • Growth floor removed. It compared a partial-year forecast remainder against a full prior year and inflated it to clear an annual growth bar, collapsing all twelve models into a five-CVE band. Bias is now handled by log-space modelling instead.
  • Constraint config wired up. The whole config document was being passed to a class that read flat keys, so every configured value was silently ignored.
  • Forecast tracker fixed. A schema key mismatch raised KeyError on every run behind a bare except; roughly nine months of daily forecast vintages were lost.
  • Rankings table alignment. Seven column headers, six cells — every value after MAPE rendered one column left of its heading.
  • Year selector restored (the buttons the code looked for did not exist), and the year-end projection no longer renders as part of the actuals line.
  • Forecast anchored on the live count. The projection continues from the total published as of now — the month in progress is a nowcast of what is already out plus the model's expectation for the working days that remain — rather than restarting from the last complete month, where it branched below the actuals and was overtaken within days.

Measurement

  • Rolling-origin backtesting across 24 origins replaces a single-origin score.
  • MASE is the ranking metric, with naive baselines ranked alongside every model.
  • One forecast path. Backtest and production run identical code, so the accuracy figures describe the forecast actually published.

Methodology

  • Log-space modelling with mild trend damping (φ = 0.98).
  • Business-day normalisation — months carry 20–23 business days.
  • Conformal prediction intervals with published empirical coverage.
  • Curated ensemble — a trimmed mean over models that clear the baseline.
  • One forecast path for both halves of the site. CNA forecasts now run through the same engine as the CVE forecast, rather than fitting models raw.
  • Data vintage logging, to measure how much counts get revised after publication.
  • Output validation in CI now checks what actually broke before: year totals that do not reconcile, projections leaking into the actuals series, models collapsing onto one number, and intervals that fail to contain their own forecast.
  • CNA page rebuilt. Years were hard-coded, so by September 2026 the settled 2025 total was labelled a forecast. The "2026 Forecasted" figure summed only forecast months — a four-month total shown as a year. Per-CNA model choice now uses rolling-origin MASE against a naive baseline, and a CNA whose best model cannot beat that baseline gets the baseline, rather than reporting a 160%-error model as its best.
  • Model choice is cached. Scoring every CNA by backtest on every run measured at over an hour, so selection is cached and a capped batch refreshed per run — oldest first, with new CNAs and materially grown series jumping the queue. Forecasting still runs for every CNA daily; only the scoring is amortised, holding the job to roughly five minutes.
